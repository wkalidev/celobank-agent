## Changelog

- July 14 2026: **Second audit pass** — full sweep of every module not covered by the first pass (DailyDrop, GoodDollar, Self Protocol registration, Farcaster bot, all server endpoints). Found and fixed: (1) `doCheckIn()`/`doClaimReward()` in the UI had a double-click nonce race — React state disables the button only after a render, so a fast double-click could fire two wallet transactions before either landed, causing "nonce too low" on-chain errors; fixed with a synchronous ref-based lock plus explicit fresh-nonce fetching. (2) The frontend's local intent regex matched "unstake 5" as a **stake** action (the word "stake" is a substring of "unstake"), which would have prepared the exact opposite transaction the user asked for; fixed by checking the unstake pattern first. (3) `POST /api/v1/prepare` (the documented public REST endpoint) never had an `unstake` case — only the MCP endpoint did — so any external API/SDK caller requesting `action: "unstake"` got "Unknown action"; added the missing case, validation, and OpenAPI enum entry. (4) The Farcaster bot (`src/bot/farcaster-bot.ts`) called `runAgent()` directly and had no handling for the unsigned-transaction marker used by all six write tools — if a Farcaster user triggered a write action, the bot would have publicly cast the raw internal `__CELOBANK_UNSIGNED_TX__{...}` JSON payload as a reply; fixed to detect the marker and reply with a summary + link to the web app instead. (5) SDK README's x402 changelog note listed three MCP tool names that don't exist in the codebase (`supply_aave`, `borrow_aave`, `repay_aave`, `check_in`) instead of the real ones (`save_cusd`, `swap_celo`, `stake_celo`, `unstake_celo`); corrected to match the actual `WRITE_TOOL_NAMES` set. (6) `/api/self-agent-status` and `/api/self-agent-register` had no rate limiting, inconsistent with every other public endpoint; added.
- July 14 2026: **Critical fix** (SDK, `@celobank/agent-sdk` v1.1.1) — the separately-published SDK package (`packages/agent-sdk`, used by third-party developers with their own private key) had the exact same Uniswap V3 `deadline`-in-ABI bug and missing-slippage-protection issue as the main app. Fixed identically: `deadline` removed from the `exactInputSingle` ABI, live Mento/Uniswap quoting + 1% slippage added to `swap()` and `swapTokens()`, `getAmountOut` added to `BROKER_ABI`. Version bumped to `1.1.1`; requires `npm publish` to go live on the registry (not run automatically — needs the maintainer's npm credentials).
- July 14 2026: **Critical fix** — write tools reachable via the AI chat path (`send_celo`, `swap_celo`, `swap_tokens`, `save_cusd`, `stake_celo`, `unstake_celo`) were signing and broadcasting transactions with the agent's own private key instead of returning unsigned transactions for the user to sign, contradicting the non-custodial v2 architecture. All six tools now delegate to `tools/prepare.ts` and return unsigned transactions; `/api/v1/chat` and the frontend now route those through the same wallet-signing flow as `/api/v1/prepare`. This was the primary cause of failed/misdirected on-chain transactions, especially for the 17 non-English/French languages the app advertises, since the frontend's fast-path intent regex only recognized English/French phrasing and fell back to the (previously broken) chat path for everything else.
- July 14 2026: **Critical fix** — the Uniswap V3 `exactInputSingle` ABI included a `deadline` field that does not exist on `SwapRouter02` (the router actually deployed at the configured address). This produced the wrong function selector, so every non-Mento swap (any pair besides CELO↔stablecoin — USDC, USDT, WETH, WBTC, stCELO, UBE, USDGLO, EURC) reverted on-chain. Fixed in `tools/prepare.ts`.
- July 14 2026: Added live slippage protection to all swaps — Mento V2 quotes via `Broker.getAmountOut`, Uniswap V3 quotes via `QuoterV2.quoteExactInputSingle`, both with a 1% default tolerance applied to `amountOutMin`/`amountOutMinimum`. Previously both were hardcoded to 0 (no MEV/sandwich protection).
- July 14 2026: Added `prepareUnstake()` — `unstake_celo` now returns a proper unsigned transaction (approve + withdraw) instead of a "not implemented" error on the MCP endpoint, and no longer signs with the agent wallet on the chat path.
- July 14 2026: Removed dead/duplicate custodial tool implementations from `tools/celo.ts` (unused `swapCeloTool`, `saveCUSDTool`, `getAavePositionTool` that shared the same custodial-signing bug and were never wired into the agent).
- July 14 2026: Reconciled documentation — SDK version corrected to the actually-published `1.1.0` everywhere (README, WHITEPAPER, GOODBUILDERS application, `/health`), x402 enforcement status corrected in WHITEPAPER (it is enforced — `POST /mcp` verifies/settles via the facilitator), and the WHITEPAPER §11 / `DISTRIBUTION.md` token-status contradiction resolved so both documents agree: no token is deployed, a distribution plan is proposed.
- May 30 2026: webhook url fix, active development
